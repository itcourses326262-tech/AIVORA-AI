# AIVORE: منصة توليد الصور والفيديو بالذكاء الاصطناعي

## ما هو AIVORE

AIVORE خدمة SaaS ثنائية اللغة (عربي RTL وإنجليزي LTR) لتوليد الصور والفيديوهات بالذكاء الاصطناعي. المستخدم يكتب وصفًا بالعربية أو الإنجليزية، يختار نموذجًا، فيحصل على النتيجة في الاستوديو ويحفظها في معرضه ويشاركها إن شاء. الدفع بالريال السعودي (شامل ضريبة القيمة المضافة 15%) عبر Moyasar (ميسر).

التقنية: Next.js 16 (App Router) وReact 19 وTypeScript بصرامة كاملة وTailwind 4 وقاعدة SQLite (better-sqlite3 مع Drizzle) على خادم واحد. لا تحتاج أي مفتاح خارجي للتجربة الأولى: مزوّد Demo المدمج يولّد صورًا وفيديوهات تجريبية بلا شبكة.

## المزايا

- أربع أدوات: نص إلى صورة، صورة إلى صورة، نص إلى فيديو، صورة إلى فيديو.
- **الاستوديو**: بطاقات النماذج مع السعر الحي، نسب الأبعاد، العدد والمدة والدقة، وصف سلبي وبذرة وقوة التأثير، وتحسين الوصف (بنموذج لغوي إن وُجد مفتاح، وإلا بقواعد محلية).
- **المعرض**: بحث وتصفية وتفضيل وتحديد متعدد وحذف جماعي، وصفحة تفاصيل لكل عمل مع «إعادة الاستخدام» و«تحريك هذه الصورة».
- **المشاركة**: صفحة عامة `/s/<id>` وتغذية `/explore`، والمالك يتحكم بالمشاركة لكل عمل.
- **الرصيد**: دفتر حسابات (ledger) لكل حركة، 50 رصيدًا مجانيًا عند التسجيل، واسترداد تلقائي عند فشل التوليد أو إلغائه.
- **واجهة API** بمفاتيح `avk_…` ووثائق عامة على `/docs` ومستند OpenAPI 3.1 على `/api/v1/openapi.json`.
- **الفوترة**: حزم رصيد لمرة واحدة وباقات شهرية بالريال، صفحة الدفع المستضافة لدى Moyasar (لا تمر بيانات البطاقة بخادمك)، مع رسائل بريد للإيصال ورابط التجديد والتأخر والاسترداد.
- **الحساب**: تأكيد البريد، استعادة كلمة المرور، تصدير البيانات وحذف الحساب، مفاتيح API، سجل الرصيد.
- **صفحات قانونية** (الشروط، الخصوصية، الاسترداد، الاستخدام المقبول): مسودات بالعربية والإنجليزية تنتظر مراجعة محاميك.
- **أدوات تشغيل**: أوامر إدارة (`admin`)، نسخ احتياطي واستعادة، صورة Docker جاهزة، واختبارات شاملة.

## البدء السريع (5 دقائق)

المتطلبات: Node.js 22 أو أحدث (ملف `.nvmrc`) وnpm. لا حاجة لملف `.env`.

```bash
git clone <رابط المستودع> aivore && cd aivore
npm ci
npm run dev
```

1. افتح <http://localhost:3000> (تظهر الصفحة بلغة متصفحك، وبالعربية إن لم تكن لغته إحدى اللغتين؛ يمكنك التبديل من الترويسة).
2. أنشئ حسابًا من «إنشاء حساب»: تحصل فورًا على **50 رصيدًا**.
3. افتح **الاستوديو**، اختر «AIVORE Demo Image» واكتب أي وصف ثم «توليد». الصورة التجريبية تأخذ بضع ثوانٍ (الفيديو التجريبي نحو 7 إلى 10 ثوانٍ، وهو ملف GIF متحرك).
4. لتخصيص الإعدادات انسخ `.env.example` إلى `.env.local` (يُقرأ تلقائيًا في التطوير).

البيانات تُحفظ في `./data` (قاعدة SQLite والوسائط). احذف المجلد لتبدأ من جديد.

لتشغيله في حاوية: `docker compose up -d --build` بعد نسخ `.env.example` إلى `.env` (التفاصيل في [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)).

## الإعدادات (متغيرات البيئة)

تُقرأ كلها من البيئة وتُتحقق عند أول طلب، وتُبلَّغ كل المشكلات معًا في رسالة واحدة. القيمة الفارغة تُعامل كأنها غير موجودة. المصدر الكامل مع الشروح: [`.env.example`](.env.example) و`src/server/env.ts`.

عمود «الإنتاج»: **مطلوب** = التطبيق يرفض الإقلاع أو لا يعمل صحيحًا بدونه، **موصى به** = اضبطه قبل الإطلاق، **اختياري** = للحاجة فقط.

## البنية

```
src/app/            الصفحات (marketing, auth, app) و api/v1 (الواجهة الوحيدة، تستخدمها الصفحات والمطورون)
src/components/     مكونات الواجهة: ui, layout, marketing, auth, studio, generations, gallery,
                    account, billing, docs, legal
src/lib/            كود متماثل (بلا أسرار): الكتالوج والتسعير، i18n، التحقق، OpenAPI، منطق الفوترة
src/server/         كود الخادم فقط: auth, security, credits, db, generations, jobs, providers,
                    storage, uploads, moderation, prompt, billing, email, http
scripts/            admin, worker, migrate, backup, restore, preview
drizzle/            هجرات SQL المُولَّدة (تُطبَّق تلقائيًا عند الإقلاع)
tests/  e2e/        اختبارات Vitest واختبارات Playwright
```

**مسار الطلب.** كل مسار API يمر عبر غلاف `route()`: معرّف طلب، تحديد معدل، مصادقة (ملف تعريف ارتباط الجلسة أو `Bearer avk_…`)، فحص CSRF للطلبات المعدِّلة، ثم المعالج. الأخطاء تعود بصيغة موحّدة `{ error: { code, message } }` ولا تتسرب تفاصيل داخلية.

**دورة حياة التوليد.**

```
POST /generations ─► تحقق ─► إشراف ─► [معاملة واحدة: حد النشط + سقف الميزانية اليومية + خصم الرصيد + إدخال queued]
المنفّذ: يطالب بالمهمة (queued→processing + عقد lease) ─► يعلّم «بدأ الإرسال» ─► provider.submit
        ─► (متزامن | معرّف مهمة غير متزامن) ─► استطلاع ─► تنزيل النتائج بأمان ─► تخزين ─► succeeded
أي فشل أو مهلة ─► failed + استرداد كامل   |   الإلغاء ─► canceled (استرداد كامل؛ وبعد قبول مزوّد مدفوع للمهمة تُردّ فقط أول 5 عمليات إلغاء يوميًا لكل حساب)
انهيار العملية ─► ينتهي العقد (60 ث) ─► تُستأنف المهمة بالاستطلاع، أو تفشل بعد MAX_ATTEMPTS
```

كل انتقال حالة هو compare-and-set داخل معاملة SQLite متزامنة، والحالات النهائية لا تتغير. المهمة المدفوعة التي ربما وصل إرسالها للمزوّد قبل الانهيار لا تُرسل مرة ثانية (تفشل بالرمز `interrupted` وتُسترد) تجنبًا لخصم مزدوج.

**دفتر الرصيد.** `users.credit_balance` نسخة مخبّأة، والحقيقة في جدول `credit_ledger`: صف لكل حركة (`delta` و`balance_after` و`reason` بين `signup_bonus` و`generation` و`refund` و`admin_grant` و`purchase` و`adjustment`) بمفتاح idempotency فريد. الخصم والإدخال والاسترداد تتم داخل نفس المعاملة، والرصيد لا ينزل تحت الصفر (قيد CHECK)، والاسترداد لا يتجاوز ما خُصم.

**العمليات.** عملية واحدة تحوي الخادم والمنفّذ (`WORKER_MODE=inline`) وجدولة الفوترة وجدولة تنظيف الحسابات المحذوفة. SQLite يقبل كاتبًا واحدًا على قرص واحد، لذلك تُشغَّل نسخة واحدة من التطبيق.

## الفوترة عبر Moyasar خطوة بخطوة

ما يُباع: حزم رصيد لمرة واحدة (500 / 1500 / 5000 رصيد بـ 29 / 79 / 229 ريالًا) وباقات شهرية (1000 / 3000 / 10000 رصيد بـ 49 / 139 / 449 ريالًا)، شاملة 15% ضريبة. الأسعار في `src/lib/billing/plans.ts` فقط، و`npm run admin -- billing-prices` يطبع القائمة مع الهامش. المشتري يدفع في صفحة Moyasar المستضافة، وتحدد الخوادم المبلغ والعملة والرصيد دائمًا؛ لا تُصدَّق أي قيمة يرسلها المتصفح أو البوابة قبل أن يعيد الخادم سؤال Moyasar عن الدفعة.

1. **أنشئ حسابًا** في Moyasar وفعّل وضع الاختبار. من لوحة التحكم > الإعدادات > مفاتيح API انسخ مفتاحي الاختبار (السري يبدأ بـ `sk_test_`، والعلني بـ `pk_test_`).
2. **على جهازك** ضع في `.env.local`: `BILLING_GATEWAY=moyasar` و`MOYASAR_SECRET_KEY` و`MOYASAR_PUBLISHABLE_KEY` بمفاتيح الاختبار. (بدون `BILLING_GATEWAY=moyasar` يستخدم التطوير صفحة دفع وهمية داخلية، وهي ممنوعة في الإنتاج بثلاث طرق مستقلة.)
3. **الـ webhook**: يحتاج عنوان https عامًا. في لوحة Moyasar أنشئ webhook إلى `https://<نطاقك>/api/v1/billing/webhooks/moyasar` وضع في حقل الرمز السري (`secret_token`) نفس قيمة `MOYASAR_WEBHOOK_SECRET` (16 حرفًا فأكثر). على جهازك المحلي لا يصل Moyasar إلى localhost؛ تتأكد المدفوعات عند عودة المشتري وبمطابقة خلفية خلال دقيقة تقريبًا، وتكتفي بدونه للتجربة.
4. **جرّب شراءً** ببطاقة اختبار من وثائق Moyasar، ثم راجع `npm run admin -- billing-orders` وسجل الرصيد في صفحة الحساب.
5. **الانتقال إلى الحي** (على الخادم لا على جهازك): المفاتيح الحية عبر مخزن أسرار الخادم لا عبر ملف في المستودع؛ `BILLING_GATEWAY=auto` (أو `moyasar`) و`MOYASAR_SECRET_KEY` الحي و`MOYASAR_WEBHOOK_SECRET` وأنشئ الـ webhook في وضع الإنتاج في اللوحة؛ `TRUST_PROXY=true` إلزامي خلف وسيط (وإلا يشارك كل المتصلين ميزانية معدل واحدة على مسارات الـ webhook والعودة)؛ ثم شراء حقيقي بـ 29 ريالًا واستردادها: `NODE_ENV=production npm run admin -- refund-order <ord_…>` (داخل Docker: `docker compose exec app node scripts/admin.mjs refund-order <ord_…>`).
6. **التجديد**: الاشتراك الشهري لا يخصم بطاقة تلقائيًا. قبل نهاية الشهر بثلاثة أيام يُنشأ **رابط دفع** يظهر في صفحة الفوترة `/account/billing` **ويُرسَل إلى بريد الحساب**. إن انتهى الشهر دون دفع يتحول الاشتراك إلى `past_due` ويصل **إشعار تأخر** يحمل رابط الدفع ما دام قابلًا للدفع، وبعد 7 أيام يُنهى الاشتراك وتصل **رسالة انتهاء**. هذه الرسائل الثلاث هي كل ما يُرسَل عن التجديد (لا تذكيرات إضافية بينها)، وكلها تعتمد على SMTP يعمل، وتُرسَل مرة واحدة على الأكثر لكل حدث فقد تضيع إن كان مرحّل البريد متوقفًا، لذلك تبقى صفحة الفوترة المرجع الاحتياطي.

**ما تم التحقق منه وما لم يُتحقق منه.** تمّ اختبار المحوّل والخدمات والمجدول واتفاقية الـ webhook كلها بخادم Moyasar وهمي مبني من الوثائق (حزم، اشتراكات، تجديد، فشل، استرداد كامل وجزئي، chargebacks، تكرار وتزامن وترتيب معكوس للأحداث، عدم تطابق المبلغ). **لم يُجرَّب شيء على Moyasar الحقيقي** (بيئة التطوير تحجب الوصول إليه). غير مُتحقَّق منه: شكل JSON الفعلي خارج `id/status/amount/currency/url/metadata/payments[]`، وصيغة `expired_at`، وهل تحمل دفعة الـ webhook `invoice_id` وبيانات الفاتورة، وصيغة أخطاء HTTP، وكيف يظهر الاسترداد الجزئي والـ chargeback، وأن الـ webhook يُصادَق فقط بحقل `secret_token` في الجسم، وطرق الدفع المتاحة في الصفحة المستضافة، ورسوم Moyasar (غير معلنة). جرّب كل ذلك في صندوق الاختبار قبل الإطلاق. لا توجد فاتورة ضريبية إلكترونية (ZATCA) ولا إيصال PDF.

## إعداد البريد (SMTP)

1. اختر مزوّد بريد معاملات (أي مزوّد SMTP) وأنشئ بيانات دخول SMTP.
2. اضبط `SMTP_URL=smtps://user:pass@smtp.example.com:465` (أو `smtp://…:587` لـ STARTTLS) و`EMAIL_FROM=AIVORE <no-reply@نطاقك>`. كلمات المرور التي فيها رموز خاصة تُشفَّر كنسبة مئوية داخل الرابط (مثلًا `@` تصبح `%40`).
3. **SPF وDKIM وDMARC**: أضف في DNS للنطاق الذي تُرسل منه السجلات التي يعطيك إياها المزوّد (SPF وDKIM)، واجعل `EMAIL_FROM` على نفس النطاق، وأضف سجل DMARC. بدونها تذهب رسائل التأكيد واستعادة كلمة المرور إلى البريد المزعج أو تُرفض.
4. جرّب: سجّل حسابًا جديدًا وتأكد وصول رسالة التأكيد، ثم جرّب «نسيت كلمة المرور».
5. ضبط SMTP يجعل `EMAIL_VERIFICATION=auto` يعني «مطلوب»: الحسابات الجديدة تحصل على الرصيد المجاني ولا تستطيع التوليد إلا بعد تأكيد بريدها. الحسابات الموجودة قبل تفعيله تُؤكَّد من اللافتة أو بـ `force-verify`.

أنواع الرسائل: تأكيد البريد، استعادة كلمة المرور، إشعار تغيير كلمة المرور، ترحيب، تأكيد حذف الحساب، وسبع رسائل فوترة: إيصال الدفع، رابط التجديد، إشعار التأخر، إشعار انتهاء الاشتراك، إشعار الاسترداد، تأكيد إلغاء الاشتراك، وتأكيد استئنافه. رسائل الفوترة تذهب إلى عنوان الحساب سواء أُكِّد أم لا، وتُسجَّل في جدول `email_events` داخل معاملة التغيير نفسها فلا تتكرر ولا تُرسَل لتغيير لم يحدث، وتُرسَل **مرة واحدة على الأكثر**: إن ماتت العملية بعد حجز الرسالة وقبل تسليمها، أو بقي المرحّل متوقفًا بعد المحاولة الثانية، ضاعت تلك الرسالة وسُجّل الخطأ `Email could not be delivered` (حقل `kind` يسمّي نوعها). الإيصال يذكر المبلغ والضريبة ويقول صراحةً إنه ليس فاتورة ضريبية.

**بدون SMTP لا يصل شيء إلى المشترين**: تُكتب الرسائل في `outbox.jsonl` بجوار قاعدة البيانات ويُسجَّل تحذير واحد في وضع الإنتاج. فـ SMTP شرط للفوترة وليس للحسابات وحدها. لم تُجرَّب أي رسالة عبر مرحّل SMTP حقيقي (انظر القيود).

## نموذج الأمان باختصار

- كلمات المرور: scrypt (N=2^15) بملح، وتُطبَّع NFKC، وقائمة كلمات شائعة ممنوعة.
- الجلسات: رمز عشوائي 32 بايت، يُخزَّن منه HMAC فقط بـ `SESSION_SECRET`. ملف تعريف ارتباط الجلسة `HttpOnly` و`SameSite=Lax` و`Secure` في الإنتاج. 30 يومًا منزلقة وسقف 180 يومًا. مفاتيح API تُخزَّن مجزّأة أيضًا وتُعرض مرة واحدة.
- CSRF: فحص `Origin` للطلبات المعدِّلة المصادَق عليها بملف تعريف الارتباط؛ إدارة المفاتيح وكل مسارات الفوترة (عدا قائمة الأسعار) وتغيير كلمة المرور للمتصفح فقط، فمفتاح API مسرَّب لا يستطيع إنشاء مفاتيح أو شراء رصيد.
- حدود المعدل لكل عملية (دخول 10 في الدقيقة، تسجيل 5 في الساعة للعنوان، توليد 30 في الدقيقة للمستخدم، رفع 20، وغيرها). ملاحظة: الحدود في الذاكرة لكل عملية.
- سقوف التكلفة: `MAX_ACTIVE_PER_USER` و`DAILY_UPSTREAM_BUDGET_CREDITS` وحد التسجيل اليومي لكل عنوان.
- جلب الملفات من الخارج (مخرجات المزوّدين) فقط عبر `safeFetch`: https، يتحقق من كل عنوان IP عند الاتصال، يرفض الشبكات الخاصة والـ metadata.
- الرفع: الصور فقط (PNG/JPEG/WebP)، بفحص بايتات سحرية وإعادة ترميز عبر sharp، تُحذف بيانات EXIF، ويُرفض ما فيه بيانات زائدة.
- الإشراف على الوصف: قواعد عربية وإنجليزية محلية بمقاومة للتمويه، واختياريًا فحص OpenAI عن بُعد.
- ترويسات: CSP و`X-Frame-Options: DENY` و`nosniff` وHSTS في الإنتاج وغيرها. الوسائط تُقدَّم مع `nosniff` وبصلاحية المالك أو العمل العام فقط.
- السجلات تحجب الأسرار والرموز تلقائيًا. بيانات البطاقة لا تصل إلى خادمك أبدًا.
- حقوق البيانات: تصدير JSON وحذف الحساب من صفحة الحساب (تُبقى سجلات الرصيد والفوترة بلا اسم الشخص للمحاسبة).
- تحذير: `ADMIN_EMAILS` لا يتحقق من ملكية البريد وحده؛ أنشئ المسؤولين بـ `create-user --role admin` أو `set-role`.

التفاصيل: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) الأقسام 9 و16 و18.

## القيود بصراحة

- **SQLite على نسخة واحدة**: لا تشغّل أكثر من حاوية تطبيق. التوسع الأفقي يتطلب تغيير قاعدة البيانات.
- **حدود المعدل لكل عملية** (في الذاكرة). خلف وسيط بدون `TRUST_PROXY=true` لا يمكن التمييز بين الزوار.
- **التجديد برابط دفع** يُرسَل بالبريد قبل نهاية الشهر بثلاثة أيام ويظهر في صفحة الفوترة، لا بخصم تلقائي: بعد نهاية الشهر يصل إشعار تأخر، ثم يُنهى الاشتراك بعد 7 أيام وتصل رسالة انتهاء. الرسائل تعتمد على SMTP وتُرسَل مرة واحدة على الأكثر، فمن لا يصله البريد ولا يفتح الصفحة يخسر باقته. الخصم بالتوكن غير مبني.
- **لا فاتورة ضريبية إلكترونية (ZATCA)** ولا إيصال PDF؛ الضريبة مخزنة على كل طلب، ورسالة الإيصال بالبريد تذكر المبلغ والضريبة وتنص على أنها ليست فاتورة ضريبية.
- **fal وMoyasar لم يُجرَّبا حيًّا**: بيئة التطوير تحجب مضيفيهما. الأسعار من مقتطفات صفحات النماذج وبعضها عمره شهور (`fal-flux-dev-img2img` مسعَّر بالأعلى من تسعيرتين متعارضتين).
- **SMTP لم يُجرَّب حيًّا**: كل رسائل البريد (التأكيد والاستعادة والفوترة) اختُبرت بناقل وهمي وبمرحّل يرفض الاتصال فقط، ولم تصل رسالة واحدة عبر مرحّل حقيقي. جرّبها بنفسك قبل الإطلاق (docs/LAUNCH.md، القسم 3).
- **الإلغاء بعد قبول المزوّد للمهمة** (الإلغاء والحذف): المهمة التي لم يرها المزوّد تُردّ كاملة ويتحرر حجزها من سقف `DAILY_UPSTREAM_BUDGET_CREDITS`. أما بعد أن يحملها مزوّد مدفوع فيبقى الحجز في السقف ويُقنَّن الاسترداد بأول 5 عمليات إلغاء لكل حساب خلال 24 ساعة (`MAX_REFUNDED_ACCEPTED_CANCELS_PER_DAY` في `src/server/generations/lifecycle.ts`)، فتنتهي حلقة إنشاء وإلغاء بعد نحو 6 مهام مقبولة لكل حساب، ويبقى السقف اليومي الحد الأعلى للإنفاق. الإلغاء السادس يُحاسَب.
- مزوّدا OpenAI وReplicate هيكلان فارغان؛ وواجهة S3 اختُبرت بعميل وهمي فقط.
- **الإشراف** نقطة بداية محافظة: النص المعكوس والكلمات المفصولة والصور ولهجات عربية كثيرة غير مغطاة، والقوائم العربية تحتاج مراجعة ناطق أصلي. لا توجد شاشة إدارية لمراجعة المحتوى، ولا أمر لإلغاء توليد مستخدم.
- الصور المرفوعة غير المستخدمة لا تُكنس ولا يوجد سقف تخزين للمستخدم.
- الصفحات القانونية **مسودات** (`LEGAL_DRAFT = true`) تنتظر محاميك. النص العربي كتبه مؤلفو الوحدات ولم يراجعه ناطق أصلي متخصص.
- قيود بيئة التطوير: سياسة الشبكة تحجب fal وMoyasar ومعظم المضيفين، فلم يُبنَ أو يُجرَّب Docker بنفسه هناك (انظر [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) لما تم التحقق منه).

# AIVORE: AI image and video generation platform

## What AIVORE is

AIVORE is a bilingual (Arabic RTL and English LTR) SaaS for generating images and videos with AI. A user writes a prompt in Arabic or English, picks a model, gets the result in the studio, keeps it in a gallery and can share it. Payment is in Saudi riyals (15% VAT included) through Moyasar.

Stack: Next.js 16 (App Router), React 19, strict TypeScript, Tailwind 4 and SQLite (better-sqlite3 with Drizzle) on a single server. The first run needs no external key: the built-in Demo provider produces sample images and videos without any network.

## Features

- Four tools: text to image, image to image, text to video, image to video.
- **Studio**: model cards with a live price, aspect ratios, count / duration / resolution, negative prompt, seed and strength, and a prompt enhancer (LLM when a key exists, local rules otherwise).
- **Gallery**: search, filters, favourites, multi-select and bulk delete, and a detail page per creation with "reuse settings" and "animate this image".
- **Sharing**: a public page `/s/<id>` and the `/explore` feed; the owner decides per creation.
- **Credits**: a ledger entry for every movement, 50 free credits at sign-up, automatic refunds when a generation fails or is canceled.
- **API** with `avk_…` keys, public documentation at `/docs` and an OpenAPI 3.1 document at `/api/v1/openapi.json`.
- **Billing**: one-time credit packs and monthly plans in SAR, on Moyasar's hosted payment page (card data never touches your server), with e-mails for the receipt, the renewal link, overdue plans and refunds.
- **Accounts**: e-mail confirmation, password reset, data export and account deletion, API keys, credit history.
- **Legal pages** (terms, privacy, refunds, acceptable use): Arabic and English drafts waiting for your lawyer.
- **Operations**: an admin CLI, backup and restore, a Docker image, and a large test suite.

## Quick start (5 minutes)

Requirements: Node.js 22 or newer (`.nvmrc`) and npm. No `.env` file is needed.

```bash
git clone <repository url> aivore && cd aivore
npm ci
npm run dev
```

1. Open <http://localhost:3000> (the page follows your browser's language, falling back to Arabic; switch it in the header).
2. Register: you get **50 credits** immediately.
3. Open the **Studio**, pick "AIVORE Demo Image", type any prompt and press Generate. A Demo image takes a few seconds (a Demo video about 7 to 10 seconds; it is an animated GIF).
4. To change settings copy `.env.example` to `.env.local` (read automatically in development).

Data lives in `./data` (the SQLite database and the media). Delete the folder to start over.

To run it in a container: `docker compose up -d --build` after copying `.env.example` to `.env` (details in [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)).

```
                    account, billing, docs, legal
src/lib/            isomorphic code (no secrets): catalog and pricing, i18n, validation, OpenAPI, billing rules
src/server/         server-only: auth, security, credits, db, generations, jobs, providers,
                    storage, uploads, moderation, prompt, billing, email, http
scripts/            admin, worker, migrate, backup, restore, preview
drizzle/            generated SQL migrations (applied automatically at start-up)
tests/  e2e/        Vitest and Playwright tests
```

**Request path.** Every API route goes through the `route()` wrapper: request id, rate limit, authentication (session cookie or `Bearer avk_…`), CSRF check for mutating requests, then the handler. Errors come back in one shape, `{ error: { code, message } }`, and internals never leak.

**Generation lifecycle.**

```
POST /generations ─► validate ─► moderate ─► [one tx: active limit + daily budget + debit credits + insert queued]
worker: claim (queued→processing + lease) ─► mark "submit started" ─► provider.submit
        ─► (sync outputs | async job id) ─► poll ─► download results safely ─► store ─► succeeded
any failure or timeout ─► failed + full refund   |   cancel ─► canceled (full refund; once a paid provider accepted the job only the first 5 such cancels per account per day are refunded)
process crash ─► lease expires (60 s) ─► the job is resumed by polling, or fails after MAX_ATTEMPTS
```

Every state change is a compare-and-set inside a synchronous SQLite transaction and terminal states never change. A paid job whose submit may have reached the provider before a crash is never submitted twice: it fails with the code `interrupted` and is refunded, to avoid a double charge.

**Credits ledger.** `users.credit_balance` is a cache; the truth is the `credit_ledger` table: one row per movement (`delta`, `balance_after`, `reason` among `signup_bonus`, `generation`, `refund`, `admin_grant`, `purchase`, `adjustment`) with a unique idempotency key. Debit, insert and refund happen in the same transaction, the balance can never go below zero (a CHECK constraint) and a refund can never exceed the debit.

**Processes.** One process holds the web server, the job runner (`WORKER_MODE=inline`), the billing scheduler and the deleted-account sweeper. SQLite takes one writer on one disk, so you run one app instance.

## Providers and models

- **Demo** (`ENABLE_MOCK_PROVIDER=true`): two free models with no network: `aivore-demo-image` (WebP, 1 credit per image) and `aivore-demo-video` (an animated GIF "motion preview", 2 credits per second at 480p). Output is deterministic from the prompt and seed.
- **fal.ai** (`FAL_KEY`): nine models with ids starting `fal-`: `fal-flux-schnell`, `fal-flux-2-pro`, `fal-nano-banana-pro` (text to image), `fal-nano-banana-pro-edit`, `fal-flux-dev-img2img` (image to image), `fal-wan-2-6-t2v`, `fal-veo-3-1-fast` (text to video), `fal-wan-2-6-i2v`, `fal-veo-3-1-fast-i2v` (image to video). One credit is about USD 0.004 of upstream cost; every price is the provider's price divided by 0.004 and rounded up.
- **OpenAI and Replicate**: empty stubs (`isConfigured` returns `false`); they offer no model.

**Adding a model to an existing provider (fal).** (1) Add a `ModelSpec` entry to `src/lib/catalog/models/fal.ts` with a unique id starting `fal-` (the catalog refuses duplicates). (2) Add the endpoint adapter under `src/server/providers/fal/adapters/` and register it in `FAL_ADAPTERS` keyed by the `providerModel`, because every fal endpoint has its own request body. (3) Run `modelSpecProblems(model)` from `tests/helpers/model-spec.ts` (it must return `[]`) and check the price on the provider's model page before you trust it.

**Adding a new provider.** (1) Add the id to `PROVIDER_IDS` in `src/lib/catalog/types.ts`. (2) Implement the `GenerationProvider` interface (`isConfigured`, `submit`, `poll`, optional `cancel`) under `src/server/providers/<name>/`, never touching the database or storage, and map provider errors to `ProviderError`. (3) Register it in `BUILT_IN` in `src/server/providers/registry.ts`. (4) Create its models file under `src/lib/catalog/models/` and add it to `src/lib/catalog/index.ts`. (5) Add its key to `src/server/env.ts`, `.env.example` and `tests/helpers/isolated-env.ts`. Every provider except `mock` counts as "paid" automatically: it is part of `DAILY_UPSTREAM_BUDGET_CREDITS` and its job is not re-submitted if it was cut off mid-submit.

## Billing with Moyasar, step by step

What is sold: one-time credit packs (500 / 1,500 / 5,000 credits for SAR 29 / 79 / 229) and monthly plans (1,000 / 3,000 / 10,000 credits for SAR 49 / 139 / 449), VAT included. Prices live only in `src/lib/billing/plans.ts`; `npm run admin -- billing-prices` prints the list with the margin. The buyer pays on Moyasar's hosted page. The server always decides amount, currency and credits, and nothing the browser or the gateway sends is trusted until the server has asked Moyasar's API about the payment.

1. **Create a Moyasar account** and switch the dashboard to test mode. Under Settings > API keys copy the test keys (the secret one starts with `sk_test_`, the publishable one with `pk_test_`).
2. **On your laptop** put in `.env.local`: `BILLING_GATEWAY=moyasar`, `MOYASAR_SECRET_KEY` and `MOYASAR_PUBLISHABLE_KEY` with the test keys. (Without `BILLING_GATEWAY=moyasar`, development uses an in-process fake payment page, which is forbidden in production in three independent ways.)
3. **The webhook** needs a public https address. In the Moyasar dashboard create a webhook to `https://<your domain>/api/v1/billing/webhooks/moyasar` and put the same value as `MOYASAR_WEBHOOK_SECRET` (16+ characters) in its secret-token field (`secret_token`). Moyasar cannot reach localhost; on a laptop payments are confirmed when the buyer returns and by the background reconciliation within about a minute, which is enough to try things out.
4. **Make a test purchase** with a test card from Moyasar's documentation, then check `npm run admin -- billing-orders` and the credit history on the account page.
5. **Go live** (on the server, not on your laptop): live keys through the server's secret store, never a file in the repository; `BILLING_GATEWAY=auto` (or `moyasar`), the live `MOYASAR_SECRET_KEY` and `MOYASAR_WEBHOOK_SECRET`, and a webhook created in the dashboard's live mode; `TRUST_PROXY=true` is mandatory behind a proxy (otherwise every caller shares one address budget on the webhook and return URLs); then make one real SAR 29 purchase and refund it: `NODE_ENV=production npm run admin -- refund-order <ord_...>` (in Docker: `docker compose exec app node scripts/admin.mjs refund-order <ord_...>`).
6. **Renewals**: a subscription never charges a saved card. Three days before the month ends a **payment link** is created, shown on the billing page `/account/billing` **and e-mailed to the account**. If the month ends unpaid the subscription becomes `past_due` and an **overdue notice** goes out with the payment link for as long as it can be paid; 7 days later the subscription is `expired` and an **expiry notice** follows. Those three messages are everything that is sent about a renewal (no further reminders between them), all of them need a working SMTP relay, and each is sent at most once per event and can be lost while the relay is down, so the billing page remains the fallback.

**Verified and not verified.** The adapter, services, scheduler and webhook handling are tested end to end against a fake Moyasar built from its documentation (packs, plans, renewal, failure, full and partial refunds, chargebacks, duplicated / concurrent / reordered events, amount mismatch). **Nothing has been run against the real Moyasar** (the development environment blocks it). UNVERIFIED: the real JSON beyond `id/status/amount/currency/url/metadata/payments[]`, the format of `expired_at`, whether the webhook payment carries `invoice_id` and the invoice metadata, the HTTP error body, how a partial refund and a chargeback appear, that webhooks are authenticated only by the `secret_token` body field, the payment methods on the hosted page and Moyasar's fees (not public). Try all of it in the sandbox before launch. There is no electronic tax invoice (ZATCA) and no PDF receipt.

## E-mail (SMTP) setup

1. Pick a transactional e-mail provider (any SMTP service) and create SMTP credentials.
2. Set `SMTP_URL=smtps://user:pass@smtp.example.com:465` (or `smtp://...:587` for STARTTLS) and `EMAIL_FROM=AIVORE <no-reply@your-domain>`. Special characters in the password must be percent-encoded inside the URL (`@` becomes `%40`).
3. **SPF, DKIM and DMARC**: add the records your provider gives you to the DNS of the domain you send from, keep `EMAIL_FROM` on that domain, and publish a DMARC record. Without them confirmation and password-reset messages land in spam or are rejected.
4. Test: register a new account and check the confirmation message arrives, then try "Forgot password".
5. With SMTP set, `EMAIL_VERIFICATION=auto` means "required": new accounts get the free credits and can generate only after confirming their address. Accounts that existed before you turned it on confirm through the banner or with `force-verify`.

Message kinds: e-mail confirmation, password reset, password-changed notice, welcome, account-deleted notice, and seven billing messages: payment receipt, renewal link, overdue notice, expiry notice, refund notice, cancellation confirmation and resume confirmation. Billing messages go to the account address whether or not it is confirmed. They are recorded in the `email_events` table inside the transaction of the change itself, so they are never repeated and never sent for a change that did not happen, and they are sent **at most once**: if the process dies after a message was claimed and before it was delivered, or the relay is still down after the second attempt, that message is lost and the error `Email could not be delivered` is logged (its `kind` field names the message). The receipt states the amount and the VAT and says in so many words that it is not a tax invoice.

**Without SMTP nothing reaches buyers**: messages are written to `outbox.jsonl` next to the database and one warning is logged in production. SMTP is therefore a requirement of billing, not only of accounts. No message has been delivered through a real SMTP relay yet (see the limitations).

## Security model in short

- Passwords: scrypt (N=2^15) with a salt, NFKC-normalised, common passwords refused.
- Sessions: a random 32-byte token of which only an HMAC (keyed with `SESSION_SECRET`) is stored. The cookie is `HttpOnly`, `SameSite=Lax` and `Secure` in production. 30 days sliding, 180 days at most. API keys are stored hashed and shown once.
- CSRF: `Origin` check on mutating cookie-authenticated requests. Key management, every billing route (except the price list) and password change are browser-session only, so a leaked API key cannot mint keys or buy credits.
- Rate limits per process (login 10/min, sign-up 5/hour per address, generation 30/min per user, uploads 20/min, and more). They live in memory, per process.
- Cost caps: `MAX_ACTIVE_PER_USER`, `DAILY_UPSTREAM_BUDGET_CREDITS` and the daily sign-up cap per address.
- Fetching anything from outside (provider outputs) goes through `safeFetch` only: https, every IP checked at connect time, private networks and metadata addresses refused.
- Uploads: images only (PNG/JPEG/WebP), magic-byte check and re-encode through sharp, EXIF removed, polyglots refused.
- Prompt moderation: local Arabic and English rules that resist obfuscation, plus an optional remote OpenAI check.
- Headers: CSP, `X-Frame-Options: DENY`, `nosniff`, HSTS in production and more. Media is served with `nosniff` and only to its owner or when the generation is public.
- Logs redact secrets and tokens automatically. Card data never reaches your server.
- Data rights: JSON export and account deletion from the account page (credit and billing records are kept without the person's name, for accounting).
- Caution: `ADMIN_EMAILS` alone does not prove ownership of an address; create admins with `create-user --role admin` or `set-role`.

Details: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) sections 9, 16 and 18.

## Admin CLI cheat sheet

There is no admin dashboard; administration is a command line. On a machine: `npm run admin -- <command>`. In Docker: `docker compose exec app node scripts/admin.mjs <command>`. Billing commands that talk to Moyasar run in production mode: `NODE_ENV=production npm run admin -- ...` (the container already is).

| Command                                                              | What it does                                                                                  |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `create-user --email e --role admin --credits n [--password-stdin]`  | Creates a confirmed account (password from stdin, an environment variable or a hidden prompt) |
| `grant-credits --email e --amount n --note "..."`                    | Grants credits (ledger reason `admin_grant`)                                                  |
| `set-role --email e --role user\|admin [--force]`                    | Changes the role (the last admin is not demoted without `--force`)                            |
| `disable --email e` / `enable --email e`                             | Disables an account, signs it out everywhere and hides what it shared / re-enables            |
| `list-users [--search s] [--limit n] [--json]`                       | Lists accounts                                                                                |
| `reset-password --email e`                                           | Sets a new password and signs the user out everywhere                                         |
| `users-stats [--json]`                                               | Accounts, confirmed, new, credits held                                                        |
| `resend-verification e` / `force-verify e`                           | Mails a new confirmation link / confirms the address by hand (and grants the missing bonus)   |
| `delete-user e [--yes] [--force]`                                    | Deletes an account like the owner's own request (without `--yes` it only shows what would go) |
| `purge-deleted`                                                      | Finishes erasing deleted accounts whose files could not all be removed                        |
| `billing-orders [--status s] [--email e] [--json]`                   | Lists orders; `needs_review` ones need a person                                               |
| `refund-order ord_... [--amount-sar n.nn] [--expect-total-sar n.nn]` | Refunds through Moyasar and takes the matching credits back                                   |
| `settle-order ord_...`                                               | Asks the gateway about a payment and applies the answer (what a webhook does)                 |
| `resolve-order ord_... --note "..."`                                 | Closes an order after a person dealt with it (moves no money and no credits)                  |
| `billing-prices`                                                     | Prints the price list with VAT and margin                                                     |

Backup and restore: `npm run backup` and `npm run restore` (see [docs/OPERATIONS.md](docs/OPERATIONS.md)).

## Honest limitations

- **SQLite, one instance**: never run more than one app container. Scaling out means changing the database.
- **Rate limits are per process** (in memory). Behind a proxy without `TRUST_PROXY=true` visitors cannot be told apart.
- **Renewals are a payment link**, e-mailed three days before the month ends and shown on the billing page, not an automatic charge: after the month ends an overdue notice follows, and 7 days later the plan expires with an expiry notice. The messages depend on SMTP and are sent at most once, so a subscriber who gets no mail and never opens the page loses the plan. Token charging is not built.
- **No electronic tax invoice (ZATCA)** and no PDF receipt; the VAT is stored on each order, and the e-mailed receipt states the amount and the VAT and says it is not a tax invoice.
- **fal and Moyasar were never called live**: the development environment blocks both hosts. Prices come from model-page excerpts and some are months old (`fal-flux-dev-img2img` uses the higher of two conflicting quotes).
- **SMTP was never used live**: every e-mail (confirmation, reset, billing) was tested with a fake transport and with a relay that refuses the connection, and not one message has gone through a real relay. Try them yourself before launch (docs/LAUNCH.md, section 3).
- **Cancelling after the provider accepted a job** (cancel and delete): a job the provider never saw is refunded in full and frees its budget booking. Once a paid provider holds it, the booking stays in `DAILY_UPSTREAM_BUDGET_CREDITS` and the refund is rationed to the first 5 such cancels per account per rolling 24 hours (`MAX_REFUNDED_ACCEPTED_CANCELS_PER_DAY` in `src/server/generations/lifecycle.ts`), so a create-and-cancel loop is bounded to about 6 accepted jobs per account per day and by the budget overall. The 6th cancel is charged.
- OpenAI and Replicate are empty stubs; the S3 driver has only been tested with a fake client.
- **Moderation** is a conservative starting point: reversed text, split words, images and many Arabic dialects are not covered, and the Arabic lists need a native-speaking reviewer. There is no admin screen to review content and no command to cancel a user's generation.
- Unused uploaded images are never swept and there is no per-user storage cap.
- The legal pages are **drafts** (`LEGAL_DRAFT = true`) waiting for your lawyer. The Arabic copy was written by the module authors and not reviewed by a specialist native speaker.
- Development environment limits: its network policy blocks fal, Moyasar and most hosts, and it has no running Docker daemon, so the image build itself was never run there (see [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) for what was verified).

There is no license file in the repository (`"private": true`).
